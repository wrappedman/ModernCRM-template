# مدرن‌CRM — قالب رابط کاربری سامانه مدیریت ارتباط با مشتری

قالب کامل و آماده‌ی فرانت‌اند (فقط UI) برای سامانه CRM فارسی و راست‌چین،
ساخته‌شده با **HTML + CSS + JavaScript خالص** و بدون هیچ کتابخانه یا CDN خارجی.

- زبان برنامه: فارسی — چینش: RTL کامل
- فونت: **وزیرمتن (Vazirmatn)** — به‌صورت متغیر و همراه قالب (بدون نیاز به اینترنت)
- تم: **فقط حالت روشن** (تک‌تمه) — همه‌ی رنگ‌ها از توکن‌های CSS می‌آیند
- تولتیپ سراسری: روی همه‌ی منوها، دکمه‌ها و آیکون‌ها (لایه‌ی شناور روی `<body>`، بدون بریده‌شدن)
- پنجره‌های شناور: هر کارت را می‌توان مثل پنجره‌های ویندوز جابه‌جا، تغییر اندازه، ماکسیمایز و به لبه‌ها «اسنپ» کرد
- نمودارها: موتور سبک SVG داخلی (خطی، ستونی، حلقه‌ای، شعاعی، Sparkline)
- تقویم شمسی (جلالی) و اعداد فارسی در تمام صفحات

## شروع سریع

کافی است پوشه را با هر وب‌سروری سرو کنید (باز کردن مستقیم فایل‌ها نیز کار می‌کند):

```bash
# پایتون
python3 -m http.server 8000

# یا با Node
npx serve .
```

سپس در مرورگر به آدرس زیر بروید:

```
http://localhost:8000/index.html
```

> صفحه‌ی `index.html` نقش «نقشه‌ی قالب» را دارد و فهرست تمام صفحه‌ها را نمایش می‌دهد.
> برای دیدن برنامه، از `login.html` (صفحه ورود) یا `dashboard.html` (داشبورد) شروع کنید.

## چگونه کار می‌کند؟

### ۱) پوسته‌ی مشترک (سایدبار، تاپ‌بار)

هر صفحه فقط این ساختار را دارد و بقیه با JavaScript ساخته می‌شود:

```html
<body class="app" data-page="customers">
  <div class="app-shell" id="appShell">
    <aside class="sidebar" id="sidebar"></aside>
    <div class="main">
      <header class="topbar" id="topbar"></header>
      <main class="content"><div class="page-wrap"> … محتوای صفحه … </div></main>
    </div>
  </div>

  <div class="win-layer" id="winLayer"></div>
  <div class="toast-wrap" id="toastWrap"></div>

  <script src="assets/js/icons.js"></script>
  <script src="assets/js/data.js"></script>
  <script src="assets/js/app.js"></script>
  <script src="assets/js/windows.js"></script>
</body>
```

- `data-page` مشخص می‌کند کدام آیتم سایدبار فعال باشد.
- منوی سایدبار از `CRM_DATA.nav` ساخته می‌شود و خود `nav` از آرایه‌ی **`CRM_DATA.modules`** (بخش‌های سامانه) در `assets/js/data.js` درست می‌شود. برای افزودن صفحه، آن را به `children` بخش مربوط اضافه کنید (`id` = مقدار `data-page`).
- **قاعده‌ی منو:** هر صفحه فقط یک‌بار و فقط در یک بخش می‌آید. گروه «میز کار» تخت است (داشبورد، پیغام‌ها، تقویم، فعالیت‌ها) و گروه «بخش‌ها» آکاردئونی است: فقط بخش صفحه‌ی فعلی باز است و با باز کردن یک بخش، بقیه بسته می‌شوند. بخشی که یک صفحه دارد (حسابداری) زیرمنو نمی‌گیرد. اگر آیتم فعال پایین‌تر از دید باشد، سایدبار خودکار تا آن اسکرول می‌شود. در سایدبار جمع‌شده، کلیک روی بخش به صفحه‌ی اصلی آن می‌رود.
- همان `modules` پنل «بخش‌های سامانه» در داشبورد را هم می‌سازد (کارت هر بخش: توضیح، دو شاخص، پیوند صفحه‌ها). گزینه‌ها: `nav: false` (فقط در داشبورد)، `soon: true` (هنوز ساخته نشده؛ در منو نمی‌آید و در داشبورد «به‌زودی» است)، `links` (پیوند اضافه‌ی کارت).

| بخش | صفحه‌ها |
| --- | --- |
| مشتریان | فهرست، افزودن، پروفایل، مشخصات مشتری، اطلاعات مشتری |
| فروش | پیگیری فروش، قیف فروش، معاملات، صدور فاکتور، مشاهده فاکتورها، تسویه فاکتور، فاکتورهای رزرو شده، نامه و قرارداد، پیامک، گزارش عملکرد فروش |
| انبار | نمای کلی، تعریف محصولات، کاتالوگ کالا و خدمات، ورود، خروج اصلی، خروج فرعی، گزارش موجودی |
| پشتیبانی | تیکت‌ها، ثبت تیکت، سفر مشتری (پرونده‌ها)، گفتگو، پایگاه دانش |
| حسابداری | ثبت سند (+ پیوند کارت: مالی پرداختی‌ها، هزینه‌ها و خسارت) |
| گزارشات | همه‌ی گزارش‌ها، ۹ گزارش موتور گزارش (`report.html?r=…`)، داشبورد تحلیلی |
| تعاریف | نمای کلی، تعریف کاربران و دسترسی، نقش‌ها و امنیت ورود، دوره مالی، تعاریف اولیه، تنظیمات فاکتور، تنظیمات سیستم |
- برای صفحه‌های بدون پوسته (ورود، خطاها، چاپ) مقدار `data-shell="none"` روی `body` بگذارید.

### ۲) پنجره‌های شبیه ویندوز

هر عنصری که ویژگی `data-win` داشته باشد می‌تواند به پنجره شناور تبدیل شود.
قالب به‌صورت خودکار یک دکمه ⛶ در گوشه‌ی کارت‌های دارای `data-win` تزریق می‌کند:

```html
<div class="card" data-win="kpi-revenue"
     data-win-title="درآمد این ماه"
     data-win-sub="شاخص کلیدی عملکرد"
     data-win-icon="wallet"
     data-win-size="820x520">
  … محتوای کارت (به‌صورت خودکار داخل پنجره کلون می‌شود) …
</div>
```

| ویژگی | کاربرد |
| --- | --- |
| `data-win-open="id"` | بازکردن پنجره از هر جای دیگر (مثلاً یک دکمه) |
| `data-win-close / -max="id"` | کنترل پنجره از بیرون |
| `data-win-size="WxH"` | اندازه پیش‌فرض پنجره |
| `data-win-icon` | آیکون نوار عنوان |
| `data-win-content="#selector"` | استفاده از محتوای عنصر دیگری به‌جای خودِ عنصر |
| `data-win-detach` | پنهان‌کردن کارت اصلی وقتی پنجره باز است (مناسب صفحه میزکار) |
| `data-win-autoopen="800"` | بازکردن خودکار پنجره پس از ۸۰۰ میلی‌ثانیه |
| `data-win-nobtn` | این کارت دکمه ⛶ نگیرد |
| `data-win-max-all / -tile / -close-all` | فرمان‌های گروهی روی همه پنجره‌ها |

هر کارتی که «سربرگ» (`card-head`) داشته باشد **به‌صورت خودکار** پنجره‌شدنی است و دکمه ⛶ می‌گیرد؛
کارت‌های خلاصه (KPI) که سربرگ ندارند، در حالت هاور یک دکمه ⛶ گوشه‌ی کارت می‌گیرند.
برای خاموش‌کردن این رفتار در یک صفحه، `data-win-auto="off"` را روی `<body>` بگذارید
(صفحه‌های ورود و خطا و چاپ همین کار را می‌کنند).

امکانات: کشیدن با نوار عنوان، تغییر اندازه از ۸ جهت، ماکسیمایز با دوبار کلیک،
اسنپ به لبه‌ها با کشیدن به کناره‌ها و منوی چیدمان با نگه‌داشتن نشانگر روی دکمه ماکسیمایز؛
هر پنجره با دکمه × نوار عنوان خودش بسته می‌شود.

#### کمینه کردن و نوار ابزار پایین

- دکمه **—** (کمینه) در نوار عنوان هر پنجره، آن را پنهان و به **نوار ابزار پایین** صفحه می‌فرستد؛ وضعیت و محتوای پنجره حفظ می‌شود.
- با کلیک روی هر چیپ نوار ابزار، پنجره دوباره باز می‌شود (با همان اندازه و حالت ماکسیمایز). دکمه‌ی ⛶ همان کارت هم اگر پنجره کمینه باشد، آن را برمی‌گرداند.
- پنجره‌های کمینه‌شده **بین صفحه‌ها** هم در دسترس‌اند (تا پایان همان تب مرورگر در `sessionStorage` ذخیره می‌شوند). اگر پنجره متعلق به صفحه‌ی دیگری باشد، با کلیک روی چیپ همان صفحه باز و پنجره در آن‌جا نمایش داده می‌شود.
- دکمه × روی چیپ، پنجره را از نوار حذف می‌کند.
- نوار ابزار در `assets/js/windows.js` (ساخت و ذخیره‌سازی) و `assets/css/layout.css` (بخش F) تعریف شده و با `#crmTaskbar` شناسایی می‌شود. در موبایل و تبلت تمام‌عرض است و در دسکتاپ کنار سایدبار می‌نشیند.
- ماکسیمایز همه و چیدمان کاشی، پنجره‌های کمینه‌شده را نادیده می‌گیرند؛ «بستن همه» همه‌ی آن‌ها را هم می‌بندد.

### ۴) تغییر هویت بصری (رنگ، فونت، اندازه)

همه‌ی متغیرها در `assets/css/tokens.css` تعریف شده‌اند:

```css
:root {
  --brand-500: #5583e0;   /* آبی ملایم — رنگ اصلی (از تم مرجع) */
  --brand-600: #3f6bc9;
  --accent-500: #e8695f;  /* مرجانی — رنگ دوم */
  --ink: #101114;         /* مشکی جوهری برای حالت‌های فعال */
  --radius: 16px;         /* گردی گوشه‌ها (تا --radius-2xl: 34px) */
  --sidebar-w: 256px;     /* عرض سایدبار */
  --font: "Vazirmatn", …;
}
  --sidebar-w-collapsed: 84px;  /* عرض سایدبار جمع‌شده */
}
```

قالب تک‌تمه است (فقط روشن) و کلید `data-theme` در آن وجود ندارد. برای تغییر رنگ برند
کافی است مقادیر `--brand-*` را عوض کنید؛ دکمه‌ها، نمودارها، سایدبار و پنجره‌ها همه
به‌صورت خودکار هماهنگ می‌شوند.

#### سوییچ نما (جدولی / کارتی / تخته)

سه صفحه‌ی «مشتریان»، «کالا و خدمات» و «قیف فروش» دو نما دارند و با همین دو ویژگی
سوییچ می‌شوند (نما در `localStorage` هم به خاطر سپرده می‌شود):

```html
<button class="seg is-active" data-view-btn="table" data-view-name="customers"
        data-icon="rows" data-icon-size="15" data-tip="نمای جدولی"></button>
<button class="seg" data-view-btn="cards" data-view-name="customers"
        data-icon="grid" data-icon-size="15" data-tip="نمای کارتی"></button>

<div data-view-panel="table"> … جدول … </div>
<div data-view-panel="cards" class="d-none"> … کارت‌ها … </div>
```

پنل پنهان با رویداد `crm:view` محتوای خودش را می‌سازد (نمای کارتی مشتریان و جدول
قیف فروش به‌صورت تنبل از `CRM.data` ساخته می‌شوند). دکمه‌ی ⛶ هر ستون کانبان هم
مودال «معامله جدید» را **با همان مرحله** باز می‌کند.

#### کشوی موبایل و چیدمان واکنش‌گرا

- زیر `۱۰۲۴px` سایدبار به کشوی تمام‌قد تبدیل می‌شود: لنگر روی لبه‌ی راست (`inset-inline-start`)
  با `translateX(105%)` بیرون از صفحه، `z-index: 320` بالای پرده‌ی `sidebar-open`.
- کشو با دکمه‌ی منوی تاپ‌بار باز/بسته می‌شود، با کلیک بیرون و کلید Escape بسته می‌شود و
  در بازگشت به دسکتاپ خودکار بسته می‌شود. حالت «سایدبار جمع‌شده» در موبایل نادیده
  گرفته می‌شود تا کشو همیشه با برچسب‌ها نمایش داده شود.
- زیر `۶۴۰px`: تاپ‌بار فقط دکمه‌های ضروری را نگه می‌دارد، شبکه‌های کارتی یک‌ستونه می‌شوند،
  جدول‌ها داخل `.table-wrap` اسکرول افقی می‌گیرند، مودال‌ها تمام‌عرض و دکمه‌های سربرگ کارت
  به سطر بعد می‌روند.

#### محتوای پویا

جدول‌ها، کانبان و کارت‌هایی که با JavaScript ساخته می‌شوند، نیازی به بایند دستی ندارند:
یک واسطه‌ی سطح سند در `app.js` قلاب‌های `data-modal-open/close`، `data-drawer-open/close`،
`data-confirm`، `data-copy`، `data-print`، `data-password-toggle` و `data-dropdown-toggle`
را برای عناصری که تازه اضافه شده‌اند هم اجرا می‌کند.

#### تولتیپ سراسری

موتور تولتیپ در `assets/js/app.js` (`CRM.tip`) قرار دارد و روی <b>همه‌ی</b> عناصر
تعاملی کار می‌کند. متن تولتیپ به این ترتیب انتخاب می‌شود:

1. `data-tip` (صریح، جای‌گذاری همان‌طور که نوشته شده)
2. `aria-label`
3. متن خود دکمه (اگر معنی‌دار باشد)
4. **واژه‌نامه‌ی آیکون → فارسی** برای دکمه‌های فقط-آیکون (مثلاً `pencil` → «ویرایش»، `trash` → «حذف»)

```html
<button class="tb-icon" data-icon="bell" data-tip="اعلان‌ها"></button>
<button class="tb-icon" data-icon="pencil"></button>   <!-- خودکار: «ویرایش» -->
<button class="tb-icon" data-tip="بستن" data-tip-pos="bottom"></button>
```

لایه‌ی تولتیپ همیشه فرزند مستقیم `<body>` است (`.tip`) و با `z-index` بالاتر از
مودال، پالت فرمان و پنجره‌ها نمایش داده می‌شود؛ بنابراین هرگز زیر پنل‌ها نمی‌رود
و توسط کادرهای `overflow:hidden` بریده نمی‌شود. در لبه‌های صفحه هم جای خود را
جابه‌جا می‌کند (بالا/پایین/چپ/راست).

**ماتریس سطح دسترسی:** دو فهرست قدیمی («انتخاب فرم» و «ثبت/ویرایش/حذف») در یک جدول ادغام شده‌اند: ستون‌های دسترسی، ثبت، ویرایش، حذف؛ ردیف‌ها گروه‌بندی‌شده بر اساس ماژول. برداشتن «دسترسی» بقیه را پاک می‌کند و زدن هر مجوز، «دسترسی» را هم می‌زند. چک‌باکس گروه و سرستون «همه» حالت نیمه‌انتخاب (`indeterminate`) دارند. «کپی دسترسی از…» از الگوی نوع کاربری یا کاربر دیگر.

داده‌ها: `CRM_DATA.defUsers`، `defUserTypes`، `defUserKinds`، `permModules` (ماژول ← فرم‌ها)، `permPresets` (الگوی هر نوع کاربری)، `defPerms[کد کاربر][شناسه فرم]` (رشته‌ای از حروف `v` دسترسی، `c` ثبت، `e` ویرایش، `d` حذف؛ مثلاً `"vce"`)، `fiscalPeriods`، `basicTypes`، `basicItems` (`parent` = زیرشاخه)، `settingTypes`، `settingValues`.

کلاس‌های جدید: `.perm-table`، `.grid-mdd`، `.code-chip`، `.radio-row`، `.value-hero`، `tr.is-selected`، `.pick-item .pi-ic/.pi-count`.

### ۵) اتصال به بک‌اند

داده‌های نمایشی در `assets/js/data.js` هستند (`CRM_DATA.customers`, `CRM_DATA.deals`, …).
برای اتصال واقعی فقط همان‌جا را با فراخوانی API خود جایگزین کنید:

```js
// نمونه: جایگزینی داده نمایشی با داده سرور
fetch('/api/customers').then(r => r.json()).then(rows => {
  CRM_DATA.customers = rows;
  // سپس رندر جدول/کارت‌ها را دوباره اجرا کنید
});
```

ساختار HTML و کلاس‌ها ثابت است؛ نیازی به تغییر مارک‌آپ صفحات نیست.
